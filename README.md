# Green Chat

Веб-интерфейс для отправки и получения текстовых сообщений в Telegram через GREEN-API
Внешний вид повторяет чат web.max.ru](https://web.max.ru) (тестовое задание "Фронтенд-разработчик React").

## Возможности

- Вход по `idInstance` + `apiTokenInstance` (+ имя пользователя). Данные проверяются запросом `getStateInstance` / `getSettings`.
- Новый чат по номеру телефона получателя: "+" -> "Добавить контакт". Номер проверяется методом `checkAccount`. Он возвращает `chatId` Telegram, к которому потом привязываются ответы.
- Отправка текста 
- Получение ответов (long polling).
- Статусы сообщений: отправляется / в очереди / отправлено / доставлено / прочитано / ошибка (с кнопкой "Повторить").
- История и список чатов сохраняются локально, отдельно для каждого инстанса.
- Адаптивная вёрстка: на узком экране показывается либо список, либо чат.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # production-сборка в dist/
npm run preview    # предпросмотр сборки
npm test           # unit- и компонентные тесты (Vitest + Testing Library)
npm run lint       # ESLint
npm run typecheck  # TypeScript (strict)
```

Нужен Node.js 20+.

### Подготовка чата
Включите уведомления о входящих сообщениях. Это можно сделать прямо из приложения: баннер "Получение сообщений выключено" -> "Включить", или в разделе "Настройки".

### Ключевые решения

**Получение сообщений.** Для Telegram GREEN-API даёт два способа: HTTP API и Webhook. WebSocket нет, а webhook требует публичного сервера. Поэтому используется long polling: `receiveNotification?receiveTimeout=25` держит соединение, пока не придёт уведомление, так что задержка - одно сетевое обращение. Очередь FIFO, поэтому **каждое** уведомление удаляется (`deleteNotification`): нетекстовые, неизвестные и те, на которых упал обработчик. Иначе очередь бы встала. Повторы отсекаются по `idMessage`. При ошибках - экспоненциальная задержка до 30 с; при 401/403 - выход из сессии.

**Несколько вкладок.** Очередь уведомлений одна на инстанс. Чтобы вкладки не отбирали уведомления друг у друга, опрос ведёт одна вкладка-лидер (Web Locks API, `navigator.locks`). События она рассылает остальным через `BroadcastChannel`. Если лидер закрывается, блокировку автоматически получает следующая вкладка.

**Отправка.** `sendMessage` ставит сообщение в очередь GREEN-API: оно хранится 24 часа и уходит после авторизации аккаунта. Сообщение появляется в ленте сразу (оптимистично), затем получает `idMessage` (в очереди), а статусы уточняются уведомлениями `outgoingMessageStatus`. `sendMessage` **никогда не повторяется автоматически**: при обрыве соединения сообщение могло уже попасть в очередь, и повтор создал бы дубль. Повтор — только по кнопке пользователя. Статусы не откатываются назад (`read` не станет `delivered`).

**Чат до авторизации.** `checkAccount` не работает, пока Telegram не авторизован. В этом случае чат создаётся с `chatId` вида `79991234567@c.us` (такой формат поддерживает `sendMessage`), и сообщения встают в очередь. Когда собеседник ответит, чат автоматически переносится на настоящий `chatId` Telegram (сопоставление по номеру телефона).

**Безопасность.** `apiTokenInstance` даёт полный доступ к аккаунту, поэтому:

- по умолчанию он хранится в `sessionStorage` (удаляется при закрытии вкладки), в `localStorage` — только при "Запомнить меня";
- в production-сборку добавляется строгая CSP: только свои скрипты, соединения — только с `*.api.green-api.com`;
- токен не попадает в логи и тексты ошибок, `referrer` отключён;
- "Выйти" удаляет учётные данные и локальную историю инстанса.

**UI-компоненты** написаны с нуля, чтобы бандл оставался минимальным. Основную работу делает браузер:

- `Modal` — нативный `<dialog>` + `showModal()`: top layer, удержание фокуса, Esc, возврат фокуса;
- `Menu`, `Tooltip`, выбор страны в `PhoneField` — Popover API (top layer, закрытие по клику снаружи и Esc) плюс своя функция позиционирования с переворотом у края окна; клавиатурная навигация по паттернам WAI-ARIA;
- анимации появления и исчезновения — на CSS (`@starting-style`, `transition-behavior: allow-discrete`), с учётом `prefers-reduced-motion`.

Runtime-зависимости: `react`, `react-dom`, `zustand`, `libphonenumber-js`.
